# v0.2.0 - RKP Product Path and RKG Labs Preview

Status: Final release notes for `v0.2.0`.

Target tag: `v0.2.0`

Compare range after tag: `v0.1.0..v0.2.0`

## Summary

This release turns the repository from a broad RealityKit demo into a clearer command-first toolkit. `rkp` is now the primary product path for asset-pipeline work, `rkg` remains experimental labs, and the SwiftUI + RealityKit app is documented as a verification fixture.

## Highlights

- RKP-first product boundary across README, CLI docs, handoff notes, and release material.
- RKG remains experimental labs and is kept separate from the stable RKP teaching path.
- Local contributor workflow through `make bootstrap-dev` and `make verify-local`.
- Stronger asset gates for USDZ inspection, Blender diagnostics, direct USDZ fallback, and release checks.
- Explicit draft fallback generation through `rkp build-asset --fallback-only`.
- GitHub Actions now installs Python dev dependencies inside a workflow-local virtual environment so macOS runners do not hit PEP 668 system-package restrictions.
- `rkp doctor` now accepts the virtualenv-backed CI test command used by the workflow.
- Public onboarding polish: concise README, CI/Python/license badges, Blender support matrix, and first-good-issue candidates.
- RKG experimental labs now include generated game planning, playable archetype scaffolds, screenshot QA planning, and `rkg verify-screenshots` evidence checks.

## User-Facing Changes

### RKP Product Surface

- Clarified that `rkp` is the stable asset-pipeline toolkit and the included app is a teaching fixture.
- Added Makefile targets for developer bootstrap and local verification.
- Hardened release and asset verification around manifest parsing, USDZ inspection, XcodeGen generation, and simulator builds.
- Added direct USDZ fallback diagnostics and `--fallback-only` for deliberate non-Blender draft builds.
- Moved repeated command reference details out of README and into `Docs/cli-tool.md`.
- Updated CI to run Python install, lint, and tests through `.venv/bin/python` on macOS GitHub runners.
- Updated pipeline doctor CI validation for the same `.venv/bin/python -m unittest discover -s Tests` command.

### RKG Experimental Labs

- Added a broader `rkg` command surface for idea scoring, archetype discovery, spec validation, game planning, QA planning, generated project scaffolding, generated game verification, and store-pack checklist generation.
- Added archetypes for `target_shooter`, `lane_dodger`, `toss_physics`, `stack_puzzle`, and `wave_defense_lite`.
- Added generated shared Swift runtime pieces for state, session control, feedback, input labels, screenshot states, game rules, scene control, asset loading, fallback factories, and result overlays.
- Added `rkg verify-screenshots` so generated project screenshot evidence can be checked against a QA plan or `GameSpec.json`.
- Kept RKG explicitly marked as labs work so it does not obscure the RKP teaching path.

### Fixture and Teaching

- Split the RealityKit fixture into focused arena, target factory, hit-effect, and material helpers while preserving target fallback order.
- Clarified that target shooter is one verification fixture, not the whole product.
- Added public-facing docs for Blender support, fallback acceptance limits, and learner-sized contribution paths.
